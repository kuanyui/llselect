6. Width policy: trigger and popup

The library never sets widths. Trigger width comes from your CSS; popup always matches trigger; chosen text in trigger ellipsizes; long labels in popup wrap. Full rationale: docs/DESIGN.md → "Popup width policy".

6.1 No CSS width (baseline): trigger expands to fit, ellipsis never triggers

Demo CSS: none. The chosen long label expands the trigger to its natural width and overflows the demo pane (and possibly the page) - this is the policy in action: the library does not constrain anything. Tidy layout is the caller's CSS job; the next demos add CSS to bring this under control.

6.2 Constrained trigger: long labels wrap; trigger ellipsizes the chosen text

Demo CSS: #mount-long-wrap { max-width: 18rem }. Longest label preselected, so trigger shows ... on load. Open the popup - long labels wrap to multiple lines.

6.3 Constrained trigger + opt-in ellipsis on labels

Demo CSS: same max-width: 18rem, plus #mount-long-ellipsis .llselect-item { text-overflow: ellipsis }. Library does not auto-add title (would fight Tippy / Floating UI / etc.); this demo uses the simplest tooltip - a subclass setting el.title.

6.4 popupWidthPolicy: 'fit-content': popup grows beyond trigger

Demo CSS: #mount-long-fitcontent { max-width: 18rem } (same as 6.2). Trigger is still constrained and ellipsizes, but the popup uses popupWidthPolicy: 'fit-content' so it expands to the widest label. If the trigger is near the viewport's right edge, the popup auto-shifts left (its x can drop below the trigger's), and width clamps to the viewport.

7. Search (filter)

Set searchable: true to add a filter input inside the popup. Trigger becomes role="button", the input becomes role="combobox" with aria-activedescendant; Tab leaves the widget, Esc clears the filter then closes. IME composition is respected (filter applies on compositionend). See docs/A11Y.md and docs/DESIGN.md.

7.1 Single + searchable (default filter)

Default filterFn is case-insensitive substring on templateItem(item).
