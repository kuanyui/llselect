6. Width policy: trigger and popup

The library never sets widths. Trigger width comes from your CSS; popup always matches trigger; chosen text in trigger ellipsizes; long labels in popup wrap. Full rationale: docs/DESIGN.md → "Popup width policy".

6.1 No CSS width (baseline): trigger expands to fit, ellipsis never triggers

Demo CSS: none. Pick the long sentence in the list - the trigger expands to its natural width and overflows the demo pane (and possibly the page). This is the policy in action: the library does not constrain anything. Tidy layout is the caller's CSS job; the next demos add CSS to bring this under control. (The long entry is intentionally NOT preselected: pre-overflowing the page on first paint triggers a Firefox Android scroll quirk.)

9. Disabled

Always aria-disabled, never the native disabled attribute - so a disabled trigger / item stays hoverable and you can attach a tooltip explaining why it is disabled. Native <select> / <option disabled> make that impossible because they suppress pointer events.

10. Optgroup / grouping

Grouping is a derived projection of the flat items list: itemToGroupKeyFn maps each item to a group key (contiguous same-key items form one group; data must be pre-sorted by group). The key is the identity; groupKeyToLabelFn is a separate display projection (the i18n seam). Group headers are role="group" with an aria-hidden label; keyboard nav skips them. Custom header content is in 11.3. See docs/DESIGN.md → "Optgroup (Phase 10)".

11. Customized renderer functions

Customize what each option renders via createItemContentElFn (no subclass). It fills the option's VISIBLE content only; the library keeps the option shell + ARIA and pins each option's aria-label to itemToString, so you write zero aria-* and a screen reader announces the plain label, not the decorative icon. Group headers customize the same way via createGroupLabelContentElFn (11.3).

11.1 Single (icon + label rows)

Each row is a colored mdi icon + label. Inspect an option to see the role="option" + aria-label the library added. There is no auto-projection; the trigger mirrors the chosen row only because we pass the same renderer to createTriggerContentElFn.

12. i18n (language packs) + RTL

All chrome strings (trigger placeholder default, search aria-label + placeholder, clear x, tag remove buttons, count summary) live in the texts setting; packs from llselect/i18n fill it whole (texts: zhTW), with per-key overrides via spread. An explicit placeholder setting is app copy and wins over the pack's triggerPlaceholder default.

12.1 Pack switcher: zhTW / ja / en / ar / he (single + multi)

Switch the pack - the instances are recreated (settings are constructor-frozen). No placeholder is passed, so every trigger shows the pack's localized triggerPlaceholder default; nothing is preselected, so every change on switch comes from the pack alone. The single shows the chosen (possibly RTL) label in its trigger; the 'tags' multi gets translated remove-x buttons (inspect their aria-label); the 'count' multi shows the translated count summary directly. Open any popup - the search input's placeholder (and aria-label) and the clear x are translated everywhere. Picking ar / he also sets dir="rtl" on the mounts (the component inherits the environment's direction - there is no RTL setting): the arrow and the x buttons mirror to the LEFT like a native <select>, chips flow right-to-left, and the mixed-direction item labels reorder via bidi.

^ multi, triggerDisplay: 'tags' - translated remove x per chip
^ multi, default 'count' - translated count summary
