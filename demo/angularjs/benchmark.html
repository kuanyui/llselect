llselect + AngularJS 1.x - benchmark

Three ways to put a select in an AngularJS 1.x app, on the same data and the same page. See angularjs/README.md for what each one is.

Defaults: 3000 items, 20 widgets. Override with ?items=500&widgets=30 to watch the ratios move: the incumbent's build is linear in the item count while llselect's is flat (it builds the list only on open), so the gap between them widens as the list grows. ui-select is the one that is genuinely superlinear, per digest.

What the numbers mean

  • digest while open is the interesting column. With the dropdown open, ui-select's theme template runs ng-class="{active: $select.isActive(this), disabled: $select.isDisabled(this)}" on every row, every digest. Both functions do an indexOf over the whole item list (uiSelectController.js:317 and :358), so the cost is O(n^2) per digest. llselect has no watchers on the list at all, so a digest does not touch it.
  • <ui-llselect> is expected to land between the two: it fixes the O(n^2) by using llselect's DOM, but ui-select's markup contract forces one child scope plus one $compile link per row, which <llselect-single> does not pay.
  • The second table is the acceptance question: putting the same validation="required" on <llselect-single> must not cost more than putting it on the <select ng-options> it replaces. angular-validation is element-agnostic (it watches ctrl.$modelValue), so the difference should be widget cost only, not validation cost.
  • <select ng-options> is the incumbent baseline. Its dropdown is an OS widget, so its open and filter are n/a, not a fake 0 - the same rule docs/SPEC_BENCHMARK.md applies to the native select in the main benchmark. Its build and digest are real, and it renders every option up front rather than lazily.
  • build creates 30 widgets over 500 items each. llselect renders the item list lazily (only on open), and so does ui-select (ng-if="$select.open" on its rows), so this column is mostly trigger cost.

Honest limits of this page

  • One run, one browser, no warmup discipline. Read it as an order of magnitude, not a score.
  • All three are measured through scope.$digest() and synthetic clicks, not real input, so it is a lower bound on real perceived latency for all of them equally.
  • ui-select is loaded with its Bootstrap theme and Bootstrap's CSS; llselect uses its vanilla theme. Layout cost is not identical, and no attempt is made to equalize it.
  • The stage is off-screen, so paint is largely excluded for everyone.
