# Committee: select widget focus events, the active-option change event, the close reason

Agent-facing record of the committee convened on three event-API additions that a survey of 28 select libraries, run for this round and separate from the 33-library survey of the veto-hook round, found missing from llselect: focus events for the whole select widget (12 of 28 libraries have them), an active-option change event (7 of 28), a close reason (6 of 28) with a cancelable before-close (5 of 28). Members: Opus 4.8, Opus 5, Sonnet 4.6, Sonnet 5, Codex Sol, Codex Astra, each in a fresh read-only session with the whole brief. Codex 5.5 could not run: the installed CLI answers "not supported when using Codex with a ChatGPT account". The owner wants all three implemented in the order 1, 2, 3; the committee settles the design first.

## The brief in short

- Q1: two base settings `onFocus` / `onBlur`, fired when DOM focus enters or leaves the select widget (`rootEl`), never for a move inside it. Sub-decisions: the names; the order against `onClose` when focus leaving closes the popup; `destroy()` and `setDisabled(true)` while focused; the `relatedTarget: null` cases; the AngularJS attributes and `$setTouched`; whether a `focus()` method is needed.
- Q2: `onActiveItemChange`, fired when the `aria-activedescendant` row changes. Sub-decisions: the payload when an action row or the choose-all row is active (A: `item | undefined`; B: a discriminated union; C: items only); the firing points; a cause parameter; the name; the AngularJS attribute and the ui-select bridge's `on-highlight`.
- Q3: 3a a reason on `onClose`; 3b a reason on `onOpen`; 3c a cancelable `onBeforeClose`.

## Corrections to the brief, verified by the members

- Every `src/base.ts` line number in the brief drifted by about thirty lines: the group-language commit landed on the file while the members read it. Lesson for the next run: freeze the tree while a committee runs, or cite symbols, not lines (Opus 4.8, Opus 5, Sonnet 4.6, Sonnet 5).
- The `focusout` listener that closes the popup is attached in `open()` and detached in `close()`; it does not exist while the popup is closed, so Q1 needs its own `focusin` / `focusout` pair for the instance's whole life, gated on a listener being set (Opus 4.8, Opus 5, Sonnet 5, Codex Astra).
- There is no Escape handler on the closed trigger: `getActionFromKey` maps Escape, and Alt+ArrowUp, to Close only while open, inside the one `handleKeydown` bound to both the trigger and the filter input; `handleSlotKeydown`, Escape on a focusable control in a header or footer slot, is a tenth close path (Opus 4.8, Opus 5, Sonnet 5, Codex Astra, Codex Sol).
- No guard reads `relatedTarget === null`; the only check is `relatedTarget` inside `rootEl`. The clear-button rebuild is safe because `replaceTriggerClearButtonElInDom` focuses the new button before removing the old one (Opus 5, Sonnet 4.6, Sonnet 5, Codex Sol).
- The tag chip strip is rebuilt without such a hand-over: a focused remove button is destroyed and focus drops to `<body>`, which likely closes an open popup today and would fire a spurious `onBlur`. Pre-existing; TODO.md's "Clear-button rebuild focus pass" item (d) records part of it (Opus 4.8, Opus 5).
- `onClose` already fires during `destroy()`, because `destroy()` calls `close()` (Opus 5, Sonnet 4.6, Codex Sol).
- `onOpen` fires before the filter input receives focus, so `document.activeElement` inside `onOpen` is still the trigger (Sonnet 4.6).
- `close()` resets the active row by direct assignment, bypassing `setFocusedIndex`, `focusChooseAllRow` and `focusActionRow`; a re-render can clamp or clear the active row too (Opus 5, Sonnet 5, Codex Sol).
- `naming-conventions.md` rules "focused" as the identifier wording for the keyboard-active option and reserves "highlight" for query-match marking, so Q1a and Q2d amend the naming log; `onHighlightChange` was never open (Opus 5, Sonnet 5, Codex Sol).
- ui-select's `on-highlight` is unsupported by the bridge because it takes a row scope; ui-select evaluates it from `isActive` in the row's scope during digests, not as a change notification (Opus 5, Codex Astra). Mapped since, by the owner's D5 ruling; the "no hover" difference the members named rested on a wrong premise about ui-select, corrected in review round six (DESIGN.md "Active item change").
- `ng-change` is not strictly user-only: the directives suppress the write-back for their own model writes, and an unsuppressed `instance()` setter call reaches `$setViewValue` (Codex Astra). To verify; `angularjs/API.md` says otherwise.
- Settings are frozen by convention, with the `placeholder` and `uiTranslationPack` exceptions; the pack's message functions get `this` (Codex Astra, Codex Sol). Not material here.

## Positions and tally

### Q1 - names, order, edge cases

- 1a `onFocus` / `onBlur`: all six. `onFocusIn` / `onFocusOut` name the DOM mechanism (the DOM pair fires on every move inside the select widget, these do not); `onFocusChange(boolean)` breaks the one-setting-per-event idiom of `onOpen` / `onClose`. Opus 5 asks for a naming-log entry: "focus" means DOM focus in public event names, "active" the `aria-activedescendant` row, and the protected `focused*` family keeps its name since renaming it is breaking. Sonnet 5 keeps the names and asks the `onFocus` docstring to say that the event has no link to the active row. Sonnet 4.6 sees no collision because the `focused*` family is not public.
- 1b order when focus leaving closes the popup: `onClose` then `onBlur`: Opus 5, Sonnet 5, Codex Astra, Codex Sol (4). `onBlur` then `onClose`: Opus 4.8, Sonnet 4.6 (2). For close-first: the blur observer sees a settled select widget, `isOpened()` false, so `$setTouched` and validation run once on a quiet select widget; focus brackets the interaction on the open side already, `onFocus` before `onOpen`. For blur-first: cause before effect.
- 1c `destroy()`: no `onBlur`, all six; detach the focus listeners as the first step, before `close()` and before `replaceChildren()` drops focus, so a parting `focusout` cannot fire (Opus 5, Sonnet 5, Codex Astra, Codex Sol). `onClose` still fires from the `close()` inside `destroy()`.
- 1d `setDisabled(true)`: no `onBlur`, all six. `syncDisabledStateToDom` writes `aria-disabled` and `data-disabled`, and `syncTriggerTabindex` writes `tabindex="-1"` unless `focusableWhenDisabled` is set; neither calls `blur()`, and a focused element keeps focus under `tabindex="-1"`; an open popup closes first and focus returns to the trigger, inside `rootEl`.
- 1e guards: reuse the `relatedTarget` inside `rootEl` test, where `null` counts as "left", all six. Real blurs that must fire: a click on a non-focusable area (`relatedTarget` null); a successful clear whose button the theme then hides, so focus falls to `<body>` (Opus 5, Codex Sol). To fix or document: the chip-strip rebuild above (Opus 4.8: a `mousedown` `preventDefault` on the remove button like the popup's; Opus 5: its own fix entry); `close()` must return focus to the trigger before hiding the popup, or the hide fires an artificial blur / focus pair (Codex Astra); with `outsideClickBehavior: 'block'` the outside `mousedown` is default-prevented, focus never moves and no `onBlur` fires, while `'pass-through'` blurs (Opus 5). A real-browser pass stays necessary (Codex Sol).
- 1f AngularJS `ll-on-focus` / `ll-on-blur`: all six, event expressions inside a digest. `$setTouched` on the blur of the whole select widget: in the same commit, called out as a behavior change (`ng-touched` starts flipping, validation messages start showing) in `angularjs/API.md` with its own test: Opus 4.8, Opus 5, Sonnet 4.6, Codex Astra, Codex Sol (5); its own decision, not bundled, because it changes validation-message timing for every existing form: Sonnet 5 (1). Mechanics from the five: call `$setTouched()` before evaluating `ll-on-blur`, inside the same digest, with ngModel's own guard (`$evalAsync` inside a digest phase, `$apply` otherwise), in all three ngModel directives, `<ui-llselect>` included; never on destroy.
- 1g no `focus()` method: all six; `triggerEl` is public and already the focus target of the label click.
- Signature, all six: `onFocus: (() => void) | null` and `onBlur: (() => void) | null` on the base settings, `null` = no consumer listener and no listener attached. A programmatic `triggerEl.focus()` fires `onFocus`.

### Q2 - the active-option change event

- 2a A, `item | undefined`: Opus 4.8, Opus 5, Sonnet 4.6, Sonnet 5 (4); Opus 5 frames it as "A now, extended through a second parameter later if a real consumer appears". B, a discriminated union (`{ kind: 'item', item }` / an action row with its descriptor, and Codex Astra adds position and index / the choose-all row): Codex Astra, Codex Sol (2). For A: the footer-description use needs the item only, the union exports a type and a `kind` vocabulary for a consumer nobody has, and a second parameter can carry row identity later without breaking a one-argument handler. For B: non-item rows exist today, so representing them is not speculative, and `undefined` loses real state. Everyone: `undefined` must be documented as both "nothing is active" and "a non-item row is active".
- 2b firing points: drop none, all six: open with the initial placement, close with `undefined`, a filter re-render that moves the active row, every navigation key, typeahead, and a click that moves the active row before the change is requested. Only when the active row actually changed, items compared with `compareFn`, never by index or DOM identity, so an in-place row rebuild never re-fires (all). Implementation facts: the three chokepoints `setFocusedIndex`, `focusChooseAllRow`, `focusActionRow` cover the navigation paths, and the render clamp in `renderPopupList` assigns `focusedIndex` directly or calls `focusChooseAllRow`; all of them end in `syncFocusedIndexToDom`, which has four exits, an action row, the choose-all row, an item row, and no row when the index is out of range, as after a filter empties the list, so one dispatch after it, comparing the resolved row with the previous one, covers every path (Opus 5, rounds five and six); `close()` resets by direct assignment and needs its own `undefined` dispatch (Opus 5, Sonnet 5); coalesce per render, never expose a transient `undefined` while the list rebuilds (Codex Astra, Codex Sol); the initial placement already lands before `onOpen`, so order there is free (Opus 5); a handler may close or rebuild the select widget, so stale continuations must be abandoned (Codex Astra).
- 2c no cause parameter now: all six. A later second argument is non-breaking for ordinary handlers; only code that invokes the callback type directly or asserts its exact `Parameters<>` would notice (Codex Astra, Codex Sol).
- 2d name: `onActiveItemChange`: Opus 4.8, Opus 5, Sonnet 4.6, Sonnet 5 (4); `onActiveRowChange`: Codex Astra (1); `onActiveOptionChange`: Codex Sol (1). `onHighlightChange` rejected by all (the highlight ruling). Against `Option`: DESIGN.md keeps ARIA role words out of JS names (Opus 5). Against `Row`: the payload reports an item only (Opus 5, Sonnet 5). "Active" is already the word of A11Y.md and DESIGN.md prose for this row (Sonnet 5).
- 2e `ll-on-active-item-change` with `$item`: the four A voters; the union voters want the attribute named after their type. The bridge mapping ui-select's `on-highlight`: map it, for item rows, with the `repeat` clause's locals, and document that llselect never moves the active row on hover and reports nothing for non-item rows: Opus 4.8, Sonnet 4.6, Sonnet 5, Codex Astra, Codex Sol (5); keep it unsupported, since ui-select's attribute takes a row scope and the same attribute with a narrower contract misleads: Opus 5 (1).

### Q3 - close reason, open reason, before-close

- 3a a `meta` argument on `onClose`: all six. Reason only, no `source`: Opus 4.8, Sonnet 4.6, Sonnet 5, Codex Astra, Codex Sol (5): each close mechanism already implies its initiator, a focus or layout close has no truthful initiator, and no consumer asked; `source` plus `reason`, reusing `LLSelectChangeSource`, because DESIGN.md "Change reason" rules that reason names the operation and source the initiator: Opus 5 (1). A `meta` object lets `source` arrive later without breaking (Opus 5).
- 3a values, one per close path. Agreed by most: `'choose'` for the single-mode pick (Opus 4.8, Opus 5, Sonnet 5, Codex Sol; Sonnet 4.6 `'pick'`, Codex Astra `'itemActivate'`), `'escape'` (five; Codex Astra `'keyboard'`), `'outside'` (four; the Codex members `'outsideClick'` / `'outside-click'`), `'toggle'` for the trigger click and `toggle()` alike (five; Opus 4.8 `'pointer'` for the click and `'api'` for a `toggle()` call from code), `'api'` for `close()` (four; Opus 5 and Codex Sol `'close'`), `'disabled'` (five; Sonnet 4.6 `'set-disabled'`), `'destroy'` (all), `'hidden'` for the positioner's hide (four; the Codex members `'triggerHidden'` / `'trigger-hidden'`). Focus leaving: `'blur'`: Opus 5, Codex Astra, Codex Sol (3); `'focusout'`: Opus 4.8, Sonnet 4.6, Sonnet 5 (3). Alt+ArrowUp under `'escape'`, said in the docstring (Opus 5, Sonnet 5); its own value (Codex Sol).
- 3a rulings shared by all: a vetoed pick reports the pick's reason, since the veto stopped the value, not the close; the first effective close wins, a later request is a no-op (Codex Astra, Codex Sol); adding the parameter is not breaking for a stored `() => void` handler, only for code that calls the exported callback type itself. Mechanism: a private pending-meta field read and reset inside `close()`, default `'api'`, the shape of `changeSource` / `withUserChangeSource` (Opus 5); the trigger click calls the public `toggle()`, so the reason must be threaded through private open / close helpers (Opus 4.8).
- 3b a reason on `onOpen`: defer: Opus 5, Sonnet 5, Codex Astra, Codex Sol (4); do it with 3a: Opus 4.8, Sonnet 4.6 (2). For defer: no consumer, no TODO entry, and the open paths carry no attribution today, so it is a refactor of four call sites, not a parameter add (Sonnet 5); non-breaking to add later.
- 3c `onBeforeClose`: defer or reject: all six. The `focusout` path can never be vetoable: A11Y.md rules that focus leaving the root closes the popup and that the popup is not a focus trap, and the previous committee's "stay" ruling for a vetoed pick rests on that invariant (Opus 5, Sonnet 5). A veto on the pick would recreate "keep open after a pick" by the back door; if that need ever arrives it is a boolean setting such as `closeOnChoose` on the single select (Opus 4.8, Opus 5, Sonnet 4.6, Sonnet 5, Codex Sol); Opus 4.8 adds that the ui-select bridge could then map `close-on-select`.

### Order and cost

- The order 1, 2, 3: all six. Q1 fixes the word for focus leaving, which 3a's reason reuses, and forces the focus-versus-active naming split that Q2 follows (Opus 5).
- Cost: Q1 small (two settings, one whole-life listener pair, the `destroy()` detach, two AngularJS attributes plus `$setTouched`, one test file), Q2 small at the chokepoints but the costliest to get right (coalescing across every render path), Q3a medium (ten call sites thread a reason) with the docs moving together.
- Another round before code: none for Q1 and Q2 once the owner ratifies the naming split and `$setTouched` (Opus 5, Sonnet 5, Codex Sol); a short Q1 round on the chip-remove fix and 1b (Opus 4.8); a Q2 round on timing, reentrancy and the bridge (Codex Astra); Q3 only if 3b or 3c must ship (Codex Sol).

## Recommendation

- Q1: `onFocus` / `onBlur` as above; `onClose` before `onBlur` (4:2); no `onBlur` from `destroy()` or `setDisabled(true)`; the whole-life listener pair detached first in `destroy()`; `close()` returns focus before hiding the popup; the chip-strip hand-over fixed in the same change set, as the `mousedown` `preventDefault` the popup already uses, with the pre-existing popup-close-on-chip-removal recorded; the `'block'` outside-click case documented. AngularJS: `ll-on-focus` / `ll-on-blur`, and `$setTouched` before `ll-on-blur` inside the digest in all three directives, called out as a behavior change (5:1).
- Q2: `onActiveItemChange: ((item: T | undefined) => void) | null` (4:2), fired after `syncFocusedIndexToDom`, covering its four exits, plus `close()`, coalesced per render, only on a real change under `compareFn`; no cause parameter; the naming log gains "active" for the public event and keeps the protected `focused*` family. AngularJS: `ll-on-active-item-change` with `$item`; the bridge maps `on-highlight` for item rows with the `repeat` locals and documents the no-hover and non-item-row differences (5:1).
- Q3: 3a reason-only (5:1), `onClose: ((meta: LLSelectCloseMeta) => void) | null` with `LLSelectCloseReason = 'choose' | 'escape' | 'outside' | 'blur' | 'toggle' | 'api' | 'disabled' | 'destroy' | 'hidden'`; `'blur'` over `'focusout'` on the 3:3 tie because one word names one concept once `onBlur` ships; `'escape'` covers Alt+ArrowUp; a vetoed pick reports `'choose'`. 3b deferred (4:2). 3c deferred, the `focusout` path never vetoable, a boolean setting if keep-open-after-a-pick is ever asked for (6:0).
- Follow-ups for TODO.md / FIXME.md: the chip-strip focus hand-over; the `ng-change` user-only claim to verify; the brief-drift lesson for the committee process.

## Decisions for the owner

Outcome, the owner's answers, given one decision at a time in conversation: D1 "A"; D2 "A"; D3 "A", the owner then asking why a pre-0.1.0 package needs a behavior-change note, so the touched flag is documented in `angularjs/API.md` as the contract and no such note is written; D4 "A", with the instruction to record the decision and its reasons as a Q&A in `DESIGN.md`; D5 "A", the bridge maps `on-highlight`; D6 the owner asked whether `source` can join `meta` later, was told yes, and raised no objection to reason-only, and chose `'blur'` for the focus-leaving value ("6b A"); D7 the owner wants `onOpen` and `onClose` to take the same `meta` shape, so the open reason ships with the close reason, against the committee's 4:2 deferral; D8 presented to the owner as unanimous and needing no ruling, and the owner raised none. The unanimous Q1 sub-decisions (no `onBlur` from `destroy()` or `setDisabled(true)`, the `relatedTarget` guard, no `focus()` method, the AngularJS attributes) shipped as recommended. `DESIGN.md` records each ruling in a section for its event, written when that event ships.

Each line below states the committee's recommendation as it was put to the owner; the paragraph above states the owner's answer to it.

- D1, the naming split: "focus" is DOM focus in public event names, "active" is the `aria-activedescendant` row, the protected `focused*` family keeps its name; hence `onFocus` / `onBlur` and `onActiveItemChange`.
- D2, the order: `onClose` then `onBlur` when focus leaving closes the popup.
- D3, `$setTouched` on the select widget blur, in the same commit as `ll-on-blur`, as a documented behavior change.
- D4, the Q2 payload: `item | undefined`, with `undefined` meaning no item is active.
- D5, the bridge: map ui-select's `on-highlight` for item rows, with the documented differences.
- D6, the close reason: reason-only, the nine values above with `'blur'`.
- D7, the open reason: deferred.
- D8, the before-close veto: deferred, `focusout` never vetoable.
