## Waiting for the owner

1. The two-finger zoom in the presets, `TODO.md` "Two-finger zoom in the presets", the owner's spec in `native-select-scrolling.md` "Two-finger zoom": while the popup is open, `behaviorPresetsOfFirefoxOnWindows` blocks a two-finger zoom everywhere and keeps the popup open; `behaviorPresetsOfChromiumOnWindows` blocks one inside the popup, and at one on the trigger or outside closes the popup and lets the zoom go on; the default leaves every zoom alone. Today the library calls `scrollGestureToBehaviorFn` neither for a touch from the moment a second finger lands nor for a wheel with `ctrlKey`, so a preset cannot see a zoom. The owner must pick the API and said that they do not know which option is better; the agent recommends B. A natural next step is a design consultation of Codex Sol and Codex Astra on this question, with a neutral brief, before the owner picks.
   - A: one more kind in the existing function, `type LLSelectScrollGestureKind = 'wheel' | 'touch-start' | 'touch-drag' | 'touch-end' | 'pinch'`. Its cost: every app that already wrote its own `scrollGestureToBehaviorFn` starts to receive zoom gestures, so a function that blocks every gesture outside would block the zoom without the app knowing, and the answers say "page-scroll" for a zoom.
   - B: a separate setting, following `DESIGN.md`'s "one function per behavior group": `zoomGestureToBehaviorFn: (gesture: LLSelectZoomGesture) => LLSelectZoomGestureBehavior`, with `interface LLSelectZoomGesture { readonly zone: LLSelectScrollGestureZone }` and `type LLSelectZoomGestureBehavior = 'leave-popup-open-and-allow-page-zoom' | 'leave-popup-open-and-block-page-zoom' | 'close-popup-and-allow-page-zoom' | 'close-popup-and-block-page-zoom'`. Called once per zoom gesture while the popup is open, with the zone of the first finger. Existing functions are untouched. The owner asked whether B leads to endless combinations of zones; the agent answered that the zones are the fixed three of the scroll gestures, that the split inside and outside comes from Chromium itself, so A needs it too, and that each preset holds three answers for the zoom.
2. A probe page for the events of a two-finger zoom, which the agent offered and the owner has not answered: on Linux with a touchpad and on Windows on a touchscreen, in Firefox and in Chromium, log what reaches the page at a two-finger zoom and at Ctrl with the mouse wheel. The owner saw that a touchpad zoom acts like a phone's pinch zoom, without the new layout that Ctrl with the mouse wheel brings. As far as the agent knows, Chromium sends a touchpad pinch to the page as a wheel with `ctrlKey`, the same event as Ctrl with the mouse wheel; Firefox on Linux is not verified. If the two events cannot be told apart, a preset that blocks the touchpad zoom also blocks Ctrl with the mouse wheel.
3. Optional: a second test on the phone of MEDIUM-929. The popup now ends 4 px above the on-screen keyboard; the version the owner tested ended 8 px above it (MEDIUM-930).
