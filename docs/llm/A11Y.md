# Accessibility behavior

The keyboard, focus, and ARIA contract for llselect. This is the behavior that automated tests target. Naming / architecture rationale lives in `DESIGN.md`; code-style rules in `../../CLAUDE.md`.

## Pattern

llselect has two ARIA modes, picked by the `filterable` setting. Booleans fix the mode per instance; the predicate form (`filterable: (items) => boolean`) re-evaluates it each time the popup OPENS (never mid-open), and an inactive open cycle behaves exactly like `filterable: false`:

- **`filterable: true`** - W3C ARIA APG "Combobox with list autocomplete" (the same focus model select2 uses). The trigger is a `button` that opens the popup; focus then moves to the filter `<input role="combobox">` inside the popup, and the option list is driven from it through `aria-activedescendant`. The input is the only focusable element in the open state, so Tab behaves like a native `<select>` - one tab stop, Tab leaves the widget.
- **`filterable: false`** (default) - ARIA "Combobox (select-only)". The trigger itself is `role="combobox"` and keeps focus; `aria-activedescendant` lives on the trigger. The filter input is not displayed (it is present in the DOM with `hidden`; see `DESIGN.md`).

### Multiple selection deviates from the APG pattern

The APG combobox pattern is specified for single selection: the popup contributes ONE value to the combobox. `LLSelectSingle` follows it directly. `LLSelectMultiple` keeps the same keyboard / focus model but pairs it with an `aria-multiselectable="true"` listbox that stays open across toggles - the extension select2 and react-select also ship. There is no official APG pattern for a multi-select combobox, so this is a documented deviation, not an APG conformance claim; it needs assistive-technology validation (manual checklist in `TODO.md`).

> Status: Phase 8 has shipped. Both modes are implemented. `filterable: true` is pinned by `test/filterable.test.ts`; `filterable: false` is covered by the existing base / keyboard / outside-click / focus test files. The select-all row is built (opt-in `selectAllRow` multi setting, Phase 13); pinned by `test/select-all.test.ts`.

## Accessible name

WAI-ARIA 1.2 requires an author-supplied accessible name for the field; the library cannot invent one. Supply the `ariaLabelledBy` setting (space-separated id(s) of your visible label element(s) - preferred, keeps spoken and visible text in sync) or `ariaLabel` (a plain string). `ariaLabelledBy` wins when both are set. The `labelEl` setting is the rung below both: with neither aria setting given, the label element's id becomes the resolved `ariaLabelledBy` (an id is minted from `classIdMap.labelId` when the element has none), and the table's first column applies. `labelEl` also emulates the behavior half native `<label for>` cannot deliver on these divs: clicking the label focuses the trigger - focus only, like a native `<select>` label, never opening - and `destroy()` unwires it (`label.test.ts`). `uiTranslationPack.filterInputAriaLabel` (default `"Search"`) is only a fallback for the filter input when neither is supplied - it names the operation, not the field. Wiring (`aria-name.test.ts`):

| Element | `ariaLabelledBy` set | only `ariaLabel` set | neither |
|---|---|---|---|
| Trigger, filter inactive (`combobox`) | `aria-labelledby`=ids (value = trigger content, per combobox role) | `aria-label` | unnamed - violates WAI-ARIA 1.2 |
| Trigger, filter active (`button`) | `aria-labelledby`="ids + value-span id" - name = field name + current value | `aria-label` + chain `"trigger-id value-span-id"` (accname substitutes the trigger's own `aria-label`, same effect) | name = content only (current value, no field name) |
| Filter input (`combobox`) | `aria-labelledby`=ids | `aria-label` | `aria-label` from `uiTranslationPack.filterInputAriaLabel` |
| Listbox | `aria-labelledby`=ids | `aria-label` | unnamed |

The "value-span" in the chains above is a `hidden` root-level span next to the trigger (`classIdMap.triggerValueId`; outside it, so `triggerEl.textContent` stays the visible content) mirroring the current value as PLAIN TEXT (chosen label / `triggerCountSummary` / tag labels joined with `", "` / placeholder when empty). The chain references it instead of the visible content span so labelled controls inside rich trigger content - tag remove buttons, custom `createTriggerContentElFn` markup - never leak into the field's accessible name (e.g. a chip must announce as `Apple`, not `Apple Remove Apple`). Hidden-but-referenced elements are included by the accname algorithm by design.

## Elements, roles, ARIA

| Element | Role | Key ARIA | Focusable |
|---|---|---|---|
| Trigger, filter inactive (it IS the combobox) | `combobox` | `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`=listbox, `aria-activedescendant`=active row while open, field name via `aria-label` / `aria-labelledby` | yes - closed and open (it is the focus host) |
| Trigger, filter active (button that opens the popup) | `button` | `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`=listbox, name = field name + current value via `aria-labelledby` chain | closed: yes; open: no (`tabindex="-1"` for the open cycle) |
| Popup wrapper | none (generic) | - | no |
| Filter input | `combobox` | field name via `aria-label` / `aria-labelledby` (fallback: `aria-label` from `uiTranslationPack.filterInputAriaLabel`; no visible label), `aria-expanded="true"`, `aria-controls`=listbox, `aria-activedescendant`=active row, `aria-autocomplete="list"` | open: yes |
| Listbox | `listbox` | field name via `aria-label` / `aria-labelledby`; multi: `aria-multiselectable="true"` | no |
| Option | `option` | `aria-selected` | no |
| Select-all row | `option` (first row of the listbox) | `aria-selected` = all-selected; tri-state via icon + name | no |
| Group container (optgroup) | `group` | `aria-label`=label; disabled: `aria-disabled="true"` + `data-disabled="true"` | no |
| Group label | none | `aria-hidden="true"` (name already on the container) | no |

- The filter input is always built into the popup DOM. When `filterable: false` it carries the `hidden` attribute and is not focusable; the focus host stays the trigger (which keeps `role="combobox"`). Always-build keeps a future runtime toggle (e.g. select2-style `minimumResultsForSearch`) a CSS flip rather than a DOM rebuild. See `DESIGN.md` for the architecture rationale.
- Select-all is the first `option` in the listbox so it sits in the arrow-key ring rather than being a separate tab stop. ARIA `option` has no `mixed` state, so the indeterminate ("some selected") state is conveyed visually (checkbox icon) and through the row's accessible name (for example "Select all (3 of 10)"), not a formal ARIA attribute.

## Focus

- Open (`filterable: true`): focus moves to the filter input, and the trigger leaves the tab order for the open cycle (`tabindex="-1"`, restored on close) - the open widget is a single tab stop, so Shift+Tab exits the widget instead of landing on the trigger with the popup still open. `aria-activedescendant` points to the first chosen option, else the first option - which is the select-all row when rendered (`selectAllRow`).
- Open (`filterable: false`): focus stays on the trigger; `aria-activedescendant` lives on the trigger.
- Close, keyboard cancel (Esc; with the filter active, Esc on an already-empty filter) or single-select pick: focus returns to the trigger (filter active - the input held focus) or simply stays on it (filter inactive).
- Close, pointer / focus dismissal (outside click on a focusable element, Tab or any focus move leaving the root): focus follows the user's action and is NOT pulled back to the trigger. Only when DOM focus is still on the filter input at close time (e.g. an outside press on a non-focusable area) does it return to the trigger.
- The popup is not a focus trap.
- Mouse clicks in the option list never steal DOM focus: `mousedown` inside the list is default-prevented (except on the list element itself, keeping native scrollbar dragging intact), so the combobox host (filter input / trigger) stays focused and keyboard input keeps working after mouse-toggling options. Without this, the browser's focus fixup would focus the `tabindex="-1"` listbox.
- Opening never moves the window scroll (enforced in `open()`).
- Focus leaving the root (`focusout` whose `relatedTarget` is outside `rootEl`) closes the popup. The check is written against `rootEl.contains(next)`, so any in-popup control keeps the popup open while it holds focus.

## Keyboard - closed (focus on trigger)

| Key | Action |
|---|---|
| Enter / Space / ArrowDown / ArrowUp | open the popup |
| Tab / Shift+Tab | move to the adjacent page element (popup stays closed) |
| anything else | not intercepted |

## Keyboard - open, filter inactive (focus on trigger)

| Key | Action |
|---|---|
| ArrowDown / ArrowUp | move `aria-activedescendant` to the next / previous enabled row (clamped, no wrap; disabled rows are skipped). ArrowUp from the topmost item continues onto the select-all leading row when present. |
| PageDown / PageUp | move the active row by a fixed page size (10) |
| Home / End | jump to the first / last enabled option. Home lands on the select-all leading row when present. |
| Enter / Space | activate the active row. Multi: toggle it, keep the popup open. Single: select it and close. On the select-all row: toggle all. (Space activates here - unlike filter-active mode, there is no text field to type into.) |
| Escape / Alt+ArrowUp | close the popup; focus stays on the trigger |
| Tab / Shift+Tab | not intercepted: the native focus move leaves the widget, and focus leaving the root closes the popup. Does not change the selection. |
| printable character | not intercepted - no prefix typeahead (useless for CJK / IME input; use `filterable`) |

## Keyboard - open, filter active (focus on filter input)

| Key | Action |
|---|---|
| ArrowDown / ArrowUp | move `aria-activedescendant` to the next / previous row (clamped, no wrap). The select-all row is the topmost row. |
| PageDown / PageUp | move the active row by a fixed page size (10) |
| Enter | activate the active row. Multi: toggle it, keep the popup open. Single: select it and close. On the select-all row: toggle all. |
| printable character | append to the filter string -> live filter |
| Space | insert a space into the filter. Does NOT toggle selection - toggling is Enter or click. |
| Home / End | move the text caret, NOT first / last option. Option jumping via Home / End is intentionally not provided in this model. |
| Tab / Shift+Tab | close the popup and move focus to the next / previous page element. Does not implicitly change the selection. |
| Escape | if the filter string is non-empty, clear it (list resets to full); if already empty, close the popup and return focus to the trigger. |

Filtering is IME-aware: while an IME composition is in progress (`compositionstart` ... `compositionend`) the list is not re-filtered on each keystroke; it filters once on `compositionend`. There is no native-style prefix typeahead - it is useless for CJK / IME input, so the filter box is the only type-to-find mechanism.

## Mouse / pointer

| Target | Action |
|---|---|
| Trigger | toggle open / close |
| Option | multi: toggle that option (popup stays open); single: select + close |
| Select-all row | toggle all |
| Outside the popup | close, per `outsideClickBehavior`: `pass-through` lets the outside action still fire; `block` swallows it |

## Filtering

- Each keystroke filters `items` through `filterFn`; the listbox renders only matches. `aria-activedescendant` resets to the first match; no match -> empty listbox with no active descendant, plus a `role="status"` no-results message BELOW the listbox (text from `uiTranslationPack.popupListNoResults`; rich content via `createPopupListNoResultsContentElFn(query)` - include real text, the status region announces its TEXT content; announced once when it appears; never an option, so it stays out of the arrow-key ring).
- Filtering does not change the chosen set. A chosen item hidden by the filter stays chosen.

## Select-all (tri-state)

- Opt-in: the `selectAllRow` multi setting (default off). The row's label (visible text + accessible name) comes from `uiTranslationPack.selectAllRowLabel`; the default tri-state icon is the library's own outlined checkbox SVG (`createOutlinedCheckboxSvgEl`, `aria-hidden`; `data-chosen-state="none|some|all"` stays on the row as a CSS hook), or rich content replaces it via `createSelectAllRowContentElFn` - the accessible name then stays pinned to the counting label via `aria-label`, like custom item content.
- none chosen -> unchecked; all chosen -> checked; some chosen -> indeterminate (icon + accessible name only; `option` has no `mixed`).
- Activating: unchecked / indeterminate -> select; checked -> deselect.
- Scope (RULED, was an open question): the VISIBLE enabled subset - the filtered list while a query is active, disabled items excluded. Choices outside that subset (filtered-out or disabled) are preserved either way. The public `chooseAll` / `unchooseAll` / `toggleAll` keep their whole-list semantics.
- Ring position: the row is the FIRST OPTION, so with nothing chosen the initial `aria-activedescendant` lands on it at open (immediate keyboard discoverability; a chosen item still wins per the Focus rules). ArrowUp from the topmost item reaches it; Home lands on it (non-filter mode; in filter-active mode Home stays a caret move); up-actions clamp there; ArrowDown returns to the first enabled item. It is never a tab stop - Tab keeps meaning "leave the widget" (one-tab-stop combobox contract).

## Disabled

Two axes, both using `aria-disabled` - never the native `disabled` attribute, which would suppress the pointer / focus events a "why is this disabled" tooltip needs.

- **Whole control** (`setDisabled(true)`): the trigger gets `aria-disabled="true"` and `data-disabled="true"`; `tabindex` becomes `-1` (out of the tab order) unless `focusableWhenDisabled` is set, in which case it stays `0`. Opening is blocked (`open()` / `toggle()` / keyboard are no-ops) and an open popup closes. Keep it focusable when you want keyboard / AT users to be able to reach the disabled control to read its tooltip.
- **Individual item** (`itemDisabledFn(item)` returns true): the option gets `aria-disabled="true"` and the `*-item-disabled` class, is not selectable by click or Enter, and is skipped by keyboard navigation - Arrow / Page / Home / End land on the nearest enabled option in the direction of travel, and focus stays put if there is none. An already-chosen item that becomes disabled stays chosen (selection is retained; only user re-toggling is blocked). Bulk actions (`chooseAll` / `unchooseAll` / `toggleAll`) act on enabled items only.

## Grouping (optgroup)

Set `itemToGroupKeyFn` to render groups. Grouping is a projection of the flat list, so it changes the DOM structure but not the navigation model.

- Each group is a `role="group"` container whose accessible name is the label (`aria-label`); the visible label element is `aria-hidden="true"` so the name is announced once, not twice. Matches the APG grouped-listbox pattern.
- A rich header (`createGroupLabelContentElFn`) fills only the visible, `aria-hidden` content (icon / count badge); the accessible name still comes from `groupKeyToLabel`, so a screen reader announces the plain group name.
- Group headers are NOT options and never enter the arrow-key ring: navigation moves option-to-option and skips headers with no special-casing (they are simply not in the focusable set / `itemEls`).
- A disabled group (`groupDisabledFn(key)` returns true) marks its container `aria-disabled="true"` + `data-disabled="true"` and disables every item in it, layering on the item-level disabled contract above (not selectable, skipped by keyboard, selection retained, bulk ops skip them).
- Items whose key is `null` render ungrouped, as direct options of the listbox.

## Tags (triggerDisplay: 'tags')

`LLSelectMultiple` with `triggerDisplay: 'tags'` renders each chosen item as a chip with a remove control.

- The remove control is a `<button aria-label="Remove <label>">` (text configurable via `uiTranslationPack.tagRemoveButtonAriaLabel` - the i18n seam) with `tabindex="-1"` - out of the tab order. Clicking it removes the item and never opens the popup (the click is stopped from bubbling to the trigger).
- Keyboard users remove selections through the popup (deselect the option), not through the chips - matching select2. This keeps focusable controls out of the `combobox` trigger, which would otherwise fight `aria-activedescendant`.
- The item's name for AT is guaranteed by the remove button's `aria-label` (`itemToTagRemoveButtonAriaLabel`, default `Remove <itemToString>`), which custom chip content never changes. The chip itself is a generic `<span>` (no role), and ARIA prohibits naming `generic` elements, so the library cannot pin a name on it the way it pins `aria-label` on options. If `createTagContentElFn` renders icon-only content, include your own (visually hidden) text when the chip must be announced as more than its remove button.
- A custom remove-button icon (`createTagRemoveButtonContentElFn`) is decorative: the button keeps its `aria-label="Remove <itemToString>"` accessible name, mirroring how `createTagContentElFn` changes only visible content. (The built-in SVG helpers already set `aria-hidden`.)

## Clear button (clearable)

`clearable: true` adds an x button in the trigger that empties the selection.

- It is a `<button aria-label="Clear selection" tabindex="-1">` (text configurable via `uiTranslationPack.triggerClearButtonAriaLabel` - the i18n seam) in its own trigger slot (not inside the content, so it composes with `createTriggerContentElFn`). Out of the tab order, like the tag remove buttons.
- Clicking it empties the selection and never opens the popup (the click is stopped from bubbling). It is hidden while nothing is selected (`data-empty`).
- Keyboard users clear via the normal selection controls (deselect in the popup); the button is a pointer convenience, matching the tag remove buttons.

## Open questions

- Tab-to-commit: Tab currently closes without changing the selection. A future option could make Tab commit the active row for single-select (native selects do this in some browsers). Off by default.
- Focusable tag remove buttons: a future flag could make chip x buttons keyboard-operable (focusable + Delete = full grid-pattern chip nav). Off by default - APG has no standalone tag pattern and it conflicts with the combobox focus model. (Deliberately deferred; see "Tags".)
