## Popup header / footer slots and action rows - implementation plan (shipped; the manual passes above stay open)

Design record: `archive/popup-slots-research.md` (survey, four committee rounds, the ratified API). Process ruled by the owner for this work: write the plan, have the committee evaluate it (round 4: six GO-WITH-CHANGES, folded in below), then implement one feature per commit, each commit `npm run verify` green, and convene the whole committee for one review at the end (that end review replaces the per-fix panel review for these commits). Anything that turns out to need a new decision goes back to the owner BEFORE the work starts, never mid-way.

Invariants that hold through every step below:

- No degradation for instances that use none of the new settings: the DOM child list, the resting node count, the keyboard tables, the `tabindex` attributes and the focus-return rules stay identical, pinned by the existing tests running unchanged (jsdom has no native Tab navigation, so the tab-stop count itself is a manual-pass item, not a test pin).
- Every new listener, rebuild and refresh path is gated on the feature being used: no Esc listener without a slot element, no row refresh with both row arrays empty, no full re-render replacing an O(1) path.
- Every new overridable method's docstring follows the CLAUDE.md order: who calls it, where each param comes from, what it means and is not, the super-then-edit override shape, internals last.

## Performance (open)

- [ ] **Cache the fit-content natural-width measurement.** With `popupWidthPolicy: 'fit-content'` now the default, every reposition (each captured scroll / resize tick while the popup is open) runs the `width: max-content` measure in `positioning.ts` - a second forced layout on top of the existing height read. Cache the natural width per open cycle and re-measure only when content changes (open, `renderPopupList`, filter query changes, `setItems`); needs an invalidation hook on the positioner. Negligible for typical lists, visible on the 10k stress demos (8.1 / 8.2).

## Accepted limitations (known, deliberately not planned)

- A single set of `.d.ts` serves both ESM and CJS. TypeScript consumers on `moduleResolution: nodenext` who `require()` the package hit the classic dual-types edge (bundler / `import` consumers are unaffected). Fixing it properly means bundling declarations into per-format `.d.ts` / `.d.cts` - revisit if anyone actually hits it.
- Per-item click listeners stay (no event delegation) until a benchmark shows a win; lazy render already bounds the cost. See the event-delegation deferral in `archive/roadmap-v0.0.1.md`.
- The popup positions with `position: fixed` from INSIDE the component subtree (no body portal - rationale and the full two-class failure taxonomy in `DESIGN.md` "In-place popup (no body portal)"). Browsers WITH the Popover API (all current ones) get the implemented top-layer enhancement, which removes both failure classes; browsers WITHOUT it keep them permanently: a containing-block-creating ancestor displaces the popup, and an ancestor stacking context can trap its paint order under overlapping higher-ordered content. That residue is accepted, and a body portal stays rejected either way.
