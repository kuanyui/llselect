# Accessibility behavior

The keyboard, focus, and ARIA contract for llselect. This is the behavior that
automated tests target. Naming / architecture rationale lives in `DESIGN.md`;
code-style rules in `../CLAUDE.md`.

## Pattern

llselect has two ARIA modes, picked per instance by the `searchable` setting:

- **`searchable: true`** - W3C ARIA APG "Combobox with list autocomplete" (the
  same focus model select2 uses). The trigger is a `button` that opens the
  popup; focus then moves to the search `<input role="combobox">` inside the
  popup, and the option list is driven from it through `aria-activedescendant`.
  The input is the only focusable element in the open state, so Tab behaves
  like a native `<select>` - one tab stop, Tab leaves the widget.
- **`searchable: false`** (default) - ARIA "Combobox (select-only)". The
  trigger itself is `role="combobox"` and keeps focus; `aria-activedescendant`
  lives on the trigger. No search input is rendered (it is built but kept
  `hidden`; see `DESIGN.md`).

> Status: Phase 8 has shipped. Both modes are implemented. `searchable: true`
> is pinned by `test/searchable.test.ts`; `searchable: false` is covered by
> the existing base / keyboard / outside-click / focus test files. The
> select-all row described below is part of the target contract but not yet
> built (it lands with a future multi-select pass).

## Elements, roles, ARIA

| Element | Role | Key ARIA | Focusable |
|---|---|---|---|
| Trigger (closed-state control) | `button` | `aria-haspopup="listbox"`, `aria-expanded`, `aria-controls`=listbox | closed: yes; open: no |
| Popup wrapper | none (generic) | - | no |
| Search input | `combobox` | `aria-expanded="true"`, `aria-controls`=listbox, `aria-activedescendant`=active row, `aria-autocomplete="list"` | open: yes |
| Listbox | `listbox` | multi: `aria-multiselectable="true"` | no |
| Option | `option` | `aria-selected` | no |
| Select-all row | `option` (first row of the listbox) | `aria-selected` = all-selected; tri-state via icon + name | no |
| Group container (optgroup) | `group` | `aria-label`=label; disabled: `aria-disabled="true"` + `data-disabled="true"` | no |
| Group label | none | `aria-hidden="true"` (name already on the container) | no |

- The search input is always built into the popup DOM. When `searchable: false`
  it carries the `hidden` attribute and is not focusable; the focus host stays
  the trigger (which keeps `role="combobox"`). Always-build keeps a future
  runtime toggle (e.g. select2-style `minimumResultsForSearch`) a CSS flip
  rather than a DOM rebuild. See `DESIGN.md` for the architecture rationale.
- Select-all is the first `option` in the listbox so it sits in the arrow-key
  ring rather than being a separate tab stop. ARIA `option` has no `mixed`
  state, so the indeterminate ("some selected") state is conveyed visually
  (checkbox icon) and through the row's accessible name (for example "Select
  all (3 of 10)"), not a formal ARIA attribute.

## Focus

- Open (`searchable: true`): focus moves to the search input.
  `aria-activedescendant` points to the first chosen option, else the first
  option.
- Open (`searchable: false`): focus stays on the trigger;
  `aria-activedescendant` lives on the trigger.
- Close (Esc on empty filter / single-select pick / outside click / focus
  leaving the root): focus returns to (or stays on) the trigger.
- The popup is not a focus trap.
- Opening never moves the window scroll (enforced in `open()`).
- Focus leaving the root (`focusout` whose `relatedTarget` is outside `rootEl`)
  closes the popup. The check is written against `rootEl.contains(next)`, so any
  in-popup control keeps the popup open while it holds focus.

## Keyboard - closed (focus on trigger)

| Key | Action |
|---|---|
| Enter / Space / ArrowDown / ArrowUp | open the popup |
| Tab / Shift+Tab | move to the adjacent page element (popup stays closed) |
| anything else | not intercepted |

## Keyboard - open (focus on search input)

| Key | Action |
|---|---|
| ArrowDown / ArrowUp | move `aria-activedescendant` to the next / previous row (clamped, no wrap). The select-all row is the topmost row. |
| PageDown / PageUp | move the active row by a fixed page size (10) |
| Enter | activate the active row. Multi: toggle it, keep the popup open. Single: select it and close. On the select-all row: toggle all. |
| printable character | append to the filter string -> live filter |
| Space | insert a space into the filter. Does NOT toggle selection - toggling is Enter or click. |
| Home / End | move the text caret, NOT first / last option. Option jumping via Home / End is intentionally not provided in this model. |
| Tab / Shift+Tab | close the popup and move focus to the next / previous page element. Does not implicitly change the selection. |
| Escape | if the filter string is non-empty, clear it (list resets to full); if already empty, close the popup and return focus to the trigger. |

Filtering is IME-aware: while an IME composition is in progress
(`compositionstart` ... `compositionend`) the list is not re-filtered on each
keystroke; it filters once on `compositionend`. There is no native-style
prefix typeahead - it is useless for CJK / IME input, so the search box is the
only type-to-find mechanism.

## Mouse / pointer

| Target | Action |
|---|---|
| Trigger | toggle open / close |
| Option | multi: toggle that option (popup stays open); single: select + close |
| Select-all row | toggle all |
| Outside the popup | close, per `outsideClickBehavior`: `pass-through` lets the outside action still fire; `block` swallows it |

## Filtering

- Each keystroke filters `items` through `filterFn`; the listbox renders only
  matches. `aria-activedescendant` resets to the first match; no match -> empty
  listbox with no active descendant.
- Filtering does not change the chosen set. A chosen item hidden by the filter
  stays chosen.

## Select-all (tri-state)

- none chosen -> unchecked; all chosen -> checked; some chosen -> indeterminate
  (icon + accessible name only; `option` has no `mixed`).
- Activating: unchecked / indeterminate -> select; checked -> deselect.

## Disabled

Two axes, both using `aria-disabled` - never the native `disabled` attribute,
which would suppress the pointer / focus events a "why is this disabled" tooltip
needs.

- **Whole control** (`setDisabled(true)`): the trigger gets `aria-disabled="true"`
  and `data-disabled="true"`; `tabindex` becomes `-1` (out of the tab order)
  unless `focusableWhenDisabled` is set, in which case it stays `0`. Opening is
  blocked (`open()` / `toggle()` / keyboard are no-ops) and an open popup closes.
  Keep it focusable when you want keyboard / AT users to be able to reach the
  disabled control to read its tooltip.
- **Individual item** (`itemDisabledFn(item)` returns true): the option gets
  `aria-disabled="true"` and the `*-item-disabled` class, is not selectable by
  click or Enter, and is skipped by keyboard navigation - Arrow / Page / Home /
  End land on the nearest enabled option in the direction of travel, and focus
  stays put if there is none. An already-chosen item that becomes disabled stays
  chosen (selection is retained; only user re-toggling is blocked). Bulk actions
  (`chooseAll` / `unchooseAll` / `toggleAll`) act on enabled items only.

## Grouping (optgroup)

Set `itemToGroupKeyFn` to render groups. Grouping is a projection of the flat
list, so it changes the DOM structure but not the navigation model.

- Each group is a `role="group"` container whose accessible name is the label
  (`aria-label`); the visible label element is `aria-hidden="true"` so the name
  is announced once, not twice. Matches the APG grouped-listbox pattern.
- A rich header (`createGroupLabelContentElFn`) fills only the visible,
  `aria-hidden` content (icon / count badge); the accessible name still comes from
  `groupKeyToLabel`, so a screen reader announces the plain group name.
- Group headers are NOT options and never enter the arrow-key ring: navigation
  moves option-to-option and skips headers with no special-casing (they are
  simply not in the focusable set / `itemEls`).
- A disabled group (`groupDisabledFn(key)` returns true) marks its container
  `aria-disabled="true"` + `data-disabled="true"` and disables every item in it,
  layering on the item-level disabled contract above (not selectable, skipped by
  keyboard, selection retained, bulk ops skip them).
- Items whose key is `null` render ungrouped, as direct options of the listbox.

## Tags (triggerDisplay: 'tags')

`LLSelectMultiple` with `triggerDisplay: 'tags'` renders each chosen item as a chip
with a remove control.

- The remove control is a `<button aria-label="Remove <label>">` with
  `tabindex="-1"` - out of the tab order. Clicking it removes the item and never
  opens the popup (the click is stopped from bubbling to the trigger).
- Keyboard users remove selections through the popup (deselect the option), not
  through the chips - matching select2. This keeps focusable controls out of the
  `combobox` trigger, which would otherwise fight `aria-activedescendant`.
- The chip's accessible name for the item stays the plain `itemToString`; a custom
  `createTagContentElFn` changes only the visible content, not the name.

## Open questions

- Select-all scope: does it act on the currently filtered (visible) items, or
  on the entire list regardless of the active filter? (Leaning: filtered, so it
  is predictable when a filter is active. Not yet locked.)
- Tab-to-commit: Tab currently closes without changing the selection. A future
  option could make Tab commit the active row for single-select (native selects
  do this in some browsers). Off by default.
- Focusable tag remove buttons: a future flag could make chip x buttons
  keyboard-operable (focusable + Delete = full grid-pattern chip nav). Off by
  default - APG has no standalone tag pattern and it conflicts with the combobox
  focus model. (Deliberately deferred; see "Tags".)
